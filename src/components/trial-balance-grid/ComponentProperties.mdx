# Trial Balance Grid — Component Set

A Storybook implementation of the Figma **Trial Balance Table** component set
([source file](https://www.figma.com/design/YCIOOyXcatc7zjImBIegHP/Trial-Balance-Table)),
built to Material 3 tokens extracted directly from the file's Design Tokens page.

Four components — **Toolbar**, **Header Cell**, **Row**, **Cell** — share one
consistent "Component Properties" contract, mirrored 1:1 from the Figma
component set's own Properties panel:

|  | Property | Type | Applies to |
|---|---|---|---|
| Boolean | `sortable` | boolean | Header Cell |
| Boolean | `pinned` | boolean | Header Cell |
| Boolean | `editable` | boolean | Cell |
| Boolean | `selected` | boolean | Row |
| Boolean | `hasError` | boolean | Row, Cell |
| Text | `columnLabel` | string | Header Cell |
| Text | `cellValue` | string | Cell |
| Text | `tooltip` | string | Cell |
| Text | `searchQuery` | string | Toolbar |
| Instance swap | `leadingSlot` | node | Row — select radio |
| Instance swap | `trailingSlot` | node | Row — row action |
| Instance swap | icon slot | node | Header Cell — unfold / sort-asc / sort-desc / filter |

A boolean property and a full **variant** are deliberately different things
here, exactly as documented on the Figma Row and Cell components: `selected`
and `hasError` toggle small inline badges *independent* of the row's full
variant treatment, so a row can show an error badge without adopting the
Error variant's complete container/label recolor. See the **Row** and
**Cell** stories for both side by side.

The same principle carries over to Row's `leadingSlot`: the composed grid
fills it with a select radio whose `checked` state tracks the selected
account directly, independent of `variant` — a warning/error row keeps its
own container styling when selected instead of switching to the Selected
variant's treatment. See **Row → Error**.

## Variants

- **Row** — Default, Hover, Selected, Disabled / read-only, Error
- **Header Cell** — Default, Sorted ascending, Sorted descending, Filter active
- **Cell** — Default, Editing, Error
- **Toolbar** — Default, Search active, Filters applied

## Toolbar extensions

The composed Mock Reference App Screen grid adds a few optional controls to
Toolbar beyond the properties above — each stays hidden unless its
controlling prop is passed in, so the base Toolbar is unaffected when they're
omitted:

|  | Property | Type | Notes |
|---|---|---|---|
| Boolean | `editActive` | boolean | Shows the Edit button pressed |
| List | `searchTerms` | string[] | Committed search-term chips, shown below the search field |
| Callback | `onAddSearchTerm` | (term) => void | Fired when Enter commits the typed search text |
| Callback | `onRemoveSearchTerm` | (term) => void | Fired when a chip's remove button is clicked |
| List | `columns` | ColumnOption[] | Shows the settings (gear) button and its column-visibility menu |
| Callback | `onEdit` | () => void | Shows the Edit button; omit to hide it |
| Callback | `onExportPdf` / `onExportExcel` | () => void | Shows the Export button/menu; omit both to hide it |
| Text | `basis` | "accrual" \| "cash" | Which amounts the segmented toggle shows as active |
| Callback | `onBasisChange` | (basis) => void | Shows the Accrual/Cash toggle; omit to hide it |

See the **Toolbar** stories — Multiple search terms, Column visibility,
Edit button, Export, and Accounting basis toggle — for each in isolation.
